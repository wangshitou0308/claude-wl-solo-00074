# 电饭煲预约跨日校时引导台

面向使用数码屏电饭煲、经常把
**「预约完成时刻（几点煮好）」「延后小时数（几小时后）」「开始时刻（几点开煮）」**
搞混的长辈：照说明书或实物登记机型规则后，应用帮你核对机内时钟偏差与跨午夜日期，
按**煮制时长范围**反算所有可行设定，再用 SVG 面板**一步一确认**地带你按键，
每一步标出“本次按键、预期屏显、指示灯”，你回报实际显示一致后才继续。

纯前端：React + TypeScript + Vite + 原生 SVG + IndexedDB。
**没有后端、不联网、不收集任何信息**；全部资料只存在本机浏览器，刷新可续做，可打印“本机厨房卡”。

## 本机运行

```bash
npm install
npm run dev        # 打开终端提示的 http://127.0.0.1:5173
```

或构建后用静态产物（`dist/` 可直接放到任意静态目录）：

```bash
npm run build
npm run preview
```

## 使用流程（五步）

1. **登记机型资料**：12/24 小时制、预约含义、调时键（时分/上下）、设定粒度、最大跨度、
   煮制时长范围、是否有机内时钟，并可按实物登记每个按键与指示灯字样。
2. **核对机内时钟**：填真实现在时间与电饭煲屏显，算出快/慢几分钟。
   可选择“去把机内钟拨准”，或“不拨钟、按偏差自动换算”。跨午夜校时可勾选“明天”。
3. **填开饭时间窗**：最早能开饭 ~ 最晚要开饭，跨午夜勾选“次日”。
4. **反算可行设定**：在机型规则（含义/粒度/最大跨度/煮制范围）与时间窗约束下枚举全部可行值，
   标注预计开煮/煮好时间。
   - 若机型含义登记为“说明书没写清”，会同时枚举四类设定；
     当不同含义显示**同一个数字**（例如 `3` 既是“3 点”又是“3 小时后”），
     会打上 **“同数字 · 看灯辨认”** 标记并保留候选。
5. **逐步操作**：SVG 面板红框脉动标出本次按键，列“预期屏显 + 各灯亮/闪/灭”；
   勾选“实际一致”才进入下一步。遇到含义未知，先进入**观察模式灯**步骤，让你看灯旁小字辨认后再继续。

## 针对长辈易错点的设计

- **三类含义分清**：登记已知含义时只给该机器真正支持的设定，避免“拿倒计时机器设钟点”。
- **同数字保留候选 + 看灯**：不靠猜，进入预约后让用户观察模式灯旁的小字再确定含义。
- **机内钟偏差**：时钟类设定自动平移偏差（例：机器快 20 分钟、想真实 07:00 好 → 屏设 07:20）；
  倒计时类按真实流逝时间走、不受钟点偏差影响。
- **跨午夜**：校时与时间窗都可标记“次日/明天”，候选统一换算成绝对日期时间。
- **粒度与最大跨度**：候选只落在合法刻度内，接近最大跨度给出红色提示。
- **一步一确认**：每步必须回报“实际显示一致”；可填写实际屏显留痕。
- **误确认可撤回**：随时回到上一步重做，后续检查点作废。
- **异常从最近确认状态重算**：错过窗口、误入保温、预约取消、屏显完全不符，
  以“现在”为基准、同一时间窗重新反算；原数字仍可行就回到最近检查点，否则回候选重选。
- **规则变化旧步骤失效**：机型影响推算的字段改动后，规则指纹变化，横幅提示并要求重新校时反算。
- **刷新续做 / 打印厨房卡**：会话存 IndexedDB；运行中与完成页均可打印一页纸贴在电饭煲旁。

## 数据与隐私

- 存储：浏览器 IndexedDB（库名 `rice-cooker-guide`），键：`profiles` / `activeProfile` / `session`。
- 清除浏览器站点数据即删除全部登记。
- 无任何网络请求与第三方服务。
